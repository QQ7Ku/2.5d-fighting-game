# 02 · 战斗系统设计

版本 v2.0.3 · 逻辑帧率固定 **60Hz** · 代码 `src/game/fighter.ts`、`src/game/match.ts`

## 1. 状态机

```
            ┌──────── 受击/硬直结束 ────────┐
            ▼                               │
  intro → idle ⇄ walk ⇄ crouch        hit ──┘
            │  ├── jump → jump(air) → land
            │  ├── block（按住后方向/防御键）
            │  └── attack（普通 / 必杀 / 投技）
            └──────── ko（血量归零，不可恢复）
```

| 状态 | 可行动 | 可被打断 | 说明 |
|---|---|---|---|
| `idle` / `walk` / `crouch` | ✔ | ✔ | 可取消为任意招式 |
| `jump` | ✔（空中攻击） | ✔ | 空中不可防御、不可投 |
| `block` | ✘ | 仅投技/不可防御技 | 保留 4 帧防御粘滞，防止抖动掉防 |
| `attack` | 仅取消窗口内 | ✘（仅被无敌判定反制） | 见第 3 节 |
| `hit` | ✘ | — | 硬直帧数来自命中数据 |
| `down` | ✘ | — | 塌陷区坠落，42 帧后爬出到坑边 |
| `ko` / `win` | ✘ | — | 回合终局 |

## 2. 输入与缓冲

- **统一输入**：键盘 / 手柄 / 触屏在 `InputManager` 归一化为 `{held, pressed, axisX, axisY}`，
  战斗系统**不区分设备**。
- **输入缓冲 8 帧**：`pressed` 进入队列保留 8 帧，因此收招前 8 帧内按下的键会在可行动的第一帧生效。
- **触屏锁存**：`pointerdown` 同时写入 `pendingPress`，即使点击短于一帧也不会丢失（代价 ≤1 帧延迟）。
- **优先级**：`special > throw > heavy > medium > light`（同帧多键时取高阶动作）。
- **指令识别**（方向码 1–9，以角色朝向为"前"）：
  - `qcf`：2 → 3 → 6，容错序列 2 → 6（触屏摇杆斜向难以精确，允许跳过斜向）
  - `qcb`：2 → 1 → 4，容错 2 → 4
  - 匹配窗口：最近 20 帧
  - **触屏简版**：按住「下」再按必杀 = 后绕系；不按下 = 前绕系；两者都不满足时才退化到第一个可用必杀
- **重映射**：10 个动作 × 2 名玩家，写入 `localStorage['washangshuang.bindings.v2']`。

## 3. 招式帧数据

每招由 `MoveDef`（普通/投技手写，必杀来自已审核 Skill JSON）描述：

| 字段 | 含义 | 约束 |
|---|---|---|
| `startup / active / recovery` | 前摇/判定/后摇帧数 | 总帧 = 三者之和 |
| `hits[]` | 一个招式可含 1–4 段判定 | 每段独立 `start/end` |
| `hits[].box` | 判定框 `{x,y,w,h}`，x 为**相对角色脚底中心**的前向偏移 | 自动按朝向镜像 |
| `cancelWindow` | 可取消区间 `[起, 止]` | `[0,0]` 表示不可取消 |
| `cancelInto` | 可取消目标招式 ID | 禁止自取消与 A→B→A 循环（Schema 外的平衡审核项） |
| `moveX[]` | 指定帧赋予前向速度 | 突进/后撤 |

**取消规则**：只有**已命中或已挥空**（`hitFlags.size>0 || whiffed`）且处于 `cancelWindow` 内的招式才能取消，
防止空挥无限连。

**顿帧（hitstop）**：命中瞬间攻守双方同时冻结 N 帧（`hits[].hitstop`，格挡时 -1）。
顿帧期间不接受输入、不推进物理，但特效与镜头继续更新 —— 这是打击感的主要来源。

## 4. 判定与伤害

- **受击框**：站立 `0.84 × 1.86`，蹲下 `0.84 × 1.24`；空中沿用站立框。
- **重叠判定**：AABB 中心距比较（`rectsOverlap`），同帧每段判定只命中一次（`hitFlags`）。
- **伤害缩放**：`damage × clamp(1 - comboCount × 0.09, 0.45, 1)` —— 连段越长收益越低，下限 45%。
- **击退换算**：数据中的 `knockback.x` 是「总位移」语义，
  初速度 `v0 = knockback.x × 0.16`，地面摩擦 0.78/帧 ⇒ 实际位移 ≈ `knockback.x × 0.73`。
- **浮空**：`knockback.y > 0.01` 时赋予垂直初速，落地进入 `land`。
- **撞墙**：受击方被推到边界 ±0.35 内且速度朝墙 → 触发 `wallSplat`：
  追加一次 level 2 破坏冲击 + 额外震屏 + "撞墙"提示。

## 5. 防御

| guard 类型 | 站防 | 蹲防 |
|---|---|---|
| `mid` | ✔ | ✔ |
| `low` | ✘ | ✔ |
| `overhead` | ✔ | ✘ |
| `unblockable` | ✘ | ✘ |

- 防御成立条件：落地 + 非攻击/受击态 + 按住**背离对手**的方向或防御键。
- 格挡削血：必杀 9%，普通技 0。
- 格挡回气：防守方 +3，攻击方获得 `meterGain × 0.5`。

## 6. 投技

- 射程 1.5（`throwRange`），对手必须落地、非无敌、非 KO。
- 投技 `guard: unblockable`，**穿过防御**（格斗游戏基本规则）。
- 命中后判定为击倒（`knockdown`），击退 4.6 ⇒ 位移约 3.3，可把对手推到立柱/墙板触发中度破坏。

## 7. 资源与冷却

- 气条 0–100，起始 35；命中得 `meterGain`，被击得 60%。
- 必杀消耗 25–40，冷却 45–90 帧（防止连续改变地形，尤其是 `destructionLevel = 3` 的震地印）。

## 8. 回合与胜负

- 三局两胜，每局 99 秒；时间到按剩余血量判定，血量相同判平。
- KO 后进入 110 帧演出（KO 特写 + 慢镜推近），随后进入下一局或结算。
- 结算面板显示「胜 / 败 / 平」与判定原因。

## 9. 已量化的平衡基线（v2.0.3 实测）

| 项 | 数值 |
|---|---|
| 血量 | 1000 |
| 单次轻攻击 | 22–24 |
| 单次重攻击 | 68–78 |
| 必杀（缠丝劲三段全中，含连段缩放） | **119**（38 + 33 + 48） |
| 震地印（单段） | 92 |
| 回澜棍（两段） | 104 |
| 掷棍归巢 | 64 |
| 投技 | 86–92 |
| KO 所需有效命中 | 约 9–14 次 |
| AI 24 秒对挂机玩家造成伤害 | 新手 44 / 普通 317 / 高手 428 |

> 伤害基线口径：**已含连段缩放** `clamp(1 − comboCount × 0.09, 0.45, 1)`，取「贴身、首段起手、三段全中」条件。
> 132 是三段原始值之和，不是实战值；`skills/review/decisions.json` 与本文档已统一按 119 记账。
> 裸伤害请查 `skills/generated/*.json` 的 `hits[].damage`。

## 10. 已知取舍

- 无空中防御、无拆投、无受身 —— 属 MVP 范围外。
- 连段以「普通技 → 必杀」两段为主；三段以上依赖墙角，是有意为之（墙边高收益）。
