# 13 · 多 Agent 审核报告

> 目标：5 个维度独立打分（0–100），**均分 ≥ 80** 且无阻断项才算通过（用户决策由 ≥90 下调为 ≥80）。
> 评分规则见 `.build-log/review/RUBRIC.md`，证据索引见 `.build-log/review/INDEX.md`，
> 每轮原始报告归档在 `.build-log/review/`（第一轮在 `round1/`，第二~四轮为 `*2.md` / `*3.md` / `round4/*.md`）。

## 1. 审核方式

- **角色分工**：战斗系统 / 动画与表现 / 场景与破坏 / 移动端与可用性 / 工程与文档一致性，五个 Agent 独立评审。
- **相互隔离**：每个 Agent 只读自己的历史报告、独立跑探针，不共享结论；均不知道其他人给的分。
- **证据强制**：每条扣分必须给 `文件:行号`、命令输出片段或截图路径，无法给证据的扣分作废。
- **扣分台**：阻断 −25 / 严重 −12 / 一般 −6 / 轻微 −2；同一问题只扣一次，系统性重复出现升一级。
- **只读约束**：审核期不改源码、不跑构建；运行时证据一律取自已构建的 `dist/`（`http://localhost:4173`）。
- **修复即复验**：每轮修复后由同一角色复审，上一轮的扣分项要么消失、要么保留并标注「已提出、未修复」。

## 4. 已知取舍（不修，且写进文档）

| 项 | 为什么保留 |
|---|---|
| 沙箱内帧率只有 4–14 fps | 无 GPU，WebGL 走 SwiftShader 软件光栅；帧率数据不作为结论，只用于相对比较 |
| Firefox / Safari 未验证 | 沙箱无对应可执行文件；Chromium 系为主验证环境 |
| 移动端「本地双人」不可用 | 2P 没有触控通道，与其留个点了没反应的选项，不如置灰并提示用键盘 |
| 极低帧率下战斗节奏变慢 | `rawDt` 钳 0.1s、单帧最多补 6 步；宁可慢放也不跳帧穿模 |
| `window.__WS` 调试钩子留在产物里 | 原型阶段需要可复现的自动化验收；钩子不参与战斗逻辑，也不暴露网络能力 |

## 5. Lux3D 独立 3D 资产（v2.0.5 新增，不接入运行时）

按用户授权，本轮用 Aholo Lux3D 计费链生成原创 3D 模型与骨骼，作为**独立美术资产**留存，不替换 `dist/` 运行时角色（Lux3D 自动绑骨骨架与游戏 19 骨程序骨架不兼容）。
