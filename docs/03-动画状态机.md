# 03 · 3D 角色与动画状态机

版本 v2.0.0 · 代码 `src/view/rig.ts`、`src/view/clips.ts` · 模型来源见 ADR-0002

## 1. 骨骼层级（19 根，全部程序化生成）

```
body(动画位移根)
└── hips 0.92
    ├── spine → chest → neck → head
    │           ├── shoulderL → upperArmL → forearmL → handL
    │           └── shoulderR → upperArmR → forearmR → handR（筄山的长棍挂在 handR）
    ├── thighL → shinL → footL
    └── thighR → shinR → footR
```

- 骨骼用 `THREE.Object3D` 手搭，网格以 `CapsuleGeometry / BoxGeometry / Icosahedron` 拼装并挂在对应骨骼上。
- 整体朝向 +Z 建模，`setFacing()` 通过 `group.rotation.y = ±π/2` 转向，因此角色永远面朝镜头侧向（2.5D 侧视）。
- 两名角色共用**骨架拓扑**（19 骨），靠 `height` 缩放（1.72 / 1.84）+ 配色 + 武器区分。
- 动作数据由 `buildClips(站架)` 生成两份：拳架（`STANCE`）与持棍侧身架（`YAOSHAN_STANCE`）。
  同一套关键帧在不同站架上重新合并，23 个 Clip 因此得到不同剪影与不同出手弧线——
  不是「复制两份动画文件」，而是「一套关键帧 + 两套基础姿势」。

## 2. 动画驱动方式（两种）

| 类型 | 驱动 | 用于 |
|---|---|---|
| **时间驱动** | `clipTime += dt`，按 Clip 自身 `dur` 循环/钳制 | idle / walk / jump / hit / ko / victory |
| **进度驱动** | 外部每帧传入 `0..1`（= `moveFrame / move.total`） | 所有攻击与投技，保证动画与帧数据严格同步 |

混合方式：不是 `AnimationMixer` 的交叉淡入，而是**逐关节阻尼插值**
（`damp(current, target, λ, dt)`，λ 默认 18，攻击 26）。优点是任意两个 Clip 之间都能平滑过渡，
不需要预生成过渡片段；代价是无法做精确的 root motion。

## 3. Clip 命名契约（不得随意改名）

| Clip | 时长/循环 | 用途 |
|---|---|---|
| `idle` | 2.4s 循环 | 站架呼吸 |
| `walk_f` / `walk_b` | 0.62 / 0.72s 循环 | 前后移动 |
| `crouch` | 0.16s 保持 | 下蹲（含 rootY -0.26） |
| `jump_up` / `jump_fall` | 0.3 / 0.4s | 起跳 / 下落 |
| `land` | 0.22s | 落地缓冲 |
| `block_stand` / `block_crouch` | 0.14s | 站防 / 蹲防 |
| `hit_light` / `hit_heavy` | 0.24 / 0.42s | 轻受击 / 重受击 |
| `ko` | 0.9s | 倒地（rootY -0.62） |
| `victory` | 1.2s 循环 | 胜利动作 |
| `intro` | 1.0s | 开场 |
| `atk_light` / `atk_medium` / `atk_heavy` | 归一化 | 三段拳/棍 |
| `atk_crouch` | 归一化 | 蹲攻击（低扫） |
| `atk_air` | 归一化 | 空中攻击 |
| `atk_special_1` / `atk_special_2` | 归一化 | 前绕必杀 / 后绕必杀 |
| `throw_start` / `throw_exec` | 归一化 | 投技起手 / 摔投 |

> Skill JSON 的 `animation.clip` 字段只能取上表的值（Schema 未强制枚举，但审核环节人工核对）。

## 4. 状态 → Clip 映射表

| 战斗状态 | Clip | 驱动 |
|---|---|---|
| `idle` | `idle` | 时间 |
| `walk`（前/后） | `walk_f` / `walk_b` | 时间 |
| `crouch` | `crouch` | 时间（停留在末帧） |
| `jump`（上升/下落） | `jump_up` / `jump_fall` | 时间 |
| 落地瞬间 | `land` | 时间（一次性） |
| `block`（站/蹲） | `block_stand` / `block_crouch` | 时间 |
| `attack` | `move.clip` | **进度** |
| `hit`（伤害 <55 / ≥55） | `hit_light` / `hit_heavy` | 时间（强制重播） |
| `ko` | `ko` | 时间 |
| `win` | `victory` | 时间 |
| `down`（坠坑） | `hit_heavy` | 时间 |

一致性约束（已在 QA 中逐项核对）：
1. `attack` 状态下 `rig.clipName` 必须等于 `move.clip`；
2. `hitstop` 期间动画继续推进（只冻结逻辑），避免打击感变成"卡住"；
3. `ko` 后不接受任何状态切换，直到回合结束重置；
4. 动画不存在"缺 Clip"回退到 `idle` 的静默失败 —— `play()` 找不到 Clip 时会回到 `idle` 并打印警告（当前 0 次触发）。

## 5. 移动端降级

| 档位 | 角色处理 |
|---|---|
| 高 | 全细节（发帽、护肩、棍箍）+ 投影 |
| 中 | 全细节 + 512 阴影贴图 |
| 低 | `detailMeshes` 隐藏（发帽/护肩/棍箍）、不投影、像素比 1.0 |

LOD 说明：角色面数本身已很低（每角色约 1.2k 三角面，不含碎片），因此采用**细节物件开关**而非多级网格，
避免切换 LOD 时出现跳变。

## 6. 与战斗系统的接口

```ts
rig.play(clipName, phaseDriven, blend?, force?)
rig.setPhase(0..1)        // 仅进度驱动时使用
rig.setFacing(1 | -1)
rig.setTier('high' | 'medium' | 'low')
rig.update(dt)            // 每个逻辑帧调用一次
```

`Fighter` 是唯一调用方；`rig` 不知道血量、计时或胜负，只负责"把当前状态画成姿势"。
