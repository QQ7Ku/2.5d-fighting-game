## 2. 核心数据结构

```ts
// 输入（键盘/手柄/触屏统一）
interface InputState {
  held: Set<Btn>;            // up/down/left/right/light/medium/heavy/special/throw/guard
  pressed: Set<Btn>;         // 本帧新按下
  axisX: number;             // -1..1（触屏为模拟值）
  axisY: number;
  analog: boolean;
}

// 招式
interface MoveDef {
  id, name, kind: 'normal'|'special'|'throw',
  button, motion, startup, active, recovery, total,
  hits: HitDef[], moveX: {frame,vx,vy?}[],
  cancelInto: string[], cancelWindow: [number, number],
  clip, clipSpeed, meterCost, cooldown,
  vfx: {preset, color, scale, trail, shake}, voice, whoosh,
  requiresGround, airOk, invuln, isThrow, throwRange, knockdown
}

// 命中段
interface HitDef {
  id, start, end, box: {x,y,w,h},
  damage, hitstun, blockstun, hitstop,
  knockback: {x,y}, guard: 'mid'|'low'|'overhead'|'unblockable',
  destroy: 0|1|2|3, meterGain, fx, sfx
}
```

## 3. 命名规范

| 类别 | 规则 | 示例 |
|---|---|---|
| 角色 ID | 小写拼音 | `libin`、`yaoshan` |
| 招式 ID | `角色_分类_序号[拼音]` | `libin_n_h1`、`libin_sp1_chansi`、`libin_throw` |
| Skill JSON 文件 | `<skillId>.json` | `libin_sp1_chansi.json` |
| 动画 Clip | `atk_* / hit_* / block_* / walk_* / jump_*` | `atk_special_2` |
| 音效标签 | 小写下划线，见白名单 | `impact_heavy` |
| 可破坏物 ID | `物件-方位/序号` | `pillar-west`、`lantern-03`、`floor-mid` |
| 事件名 | `域:动作`，全小写 | `hud:health`、`destroy:collapse` |
| 资源目录 | `assets/<来源>/<用途>` | `assets/lux3d/libin_mesh_glb.glb` |
| 版本 | `2.MINOR.PATCH` | `2.0.0`、`2.0.1` |

## 4. 触屏输入事件契约

| 行为 | 事件 | 数据 |
|---|---|---|
| 摇杆按下 | `pointerdown` on `#stick-zone` | `pointerId` 绑定，单指独占 |
| 摇杆移动 | `pointermove` | 归一化到 `axisX/axisY`（死区 0.18/0.22） |
| 摇杆抬起 | `pointerup / pointercancel / lostpointercapture` | 归零 |
| 按钮按下 | `pointerdown` on `.tbtn[data-action]` | `data-action` ∈ 六键 |
| 按钮抬起 | `pointerup / pointercancel / lostpointercapture` | 多指同键时全部抬起才释放 |
| 暂停 | `#touch-pause` | 派发 `game:pause-request` |

所有触屏元素 `touch-action: none` + `preventDefault()`，并对 `document` 阻止双指缩放与 `gesturestart`。

## 5. 目录契约

| 目录 | 允许写入者 | 内容 |
|---|---|---|
| `src/core` | 总控 | 基础设施，不含玩法 |
| `src/view` | 3D/渲染 Agent | 只读 `src/data`，不得写玩法状态 |
| `src/game` | 战斗/破坏/AI Agent | 唯一可改战斗状态的地方 |
| `src/ui` | UI/音效 Agent | 只通过事件总线交互 |
| `skills/` | Skill 生成 Agent | Schema / 提示词 / 种子 / 候选 / 审核 / 入库 |
| `scene/` | 程序化场景 Agent | 参数 / 生成器 / 输出 / 记录 |
| `docs/` | 各 Agent | 各自文档 + `agents/` 自检 |
| `dist/` | 版本管理 Agent | 构建产物，**禁止手改** |

## 6. 提交与版本规范

- 提交前缀：`feat(战斗):` `fix(破坏):` `docs(接口):` `chore(构建):` `balance(技能):` `asset(场景):`
- 提交正文必须包含：影响的契约字段（如有）、对应审核编号（技能/场景）、版本号。
- 版本变更：`package.json` version 与 `docs/10-变更日志.md` 同步；`dist` 由 `npm run build` 生成，不手工修改。
- 破坏性变更（事件名、Schema 字段、Clip 名）必须：① 升 minor ② 更新本文件 ③ 通知总控 ④ 全链路回归。

## 7. 一致性自检（每次构建前）

1. `node skills/scripts/generate.mjs --check` → 0 失败
2. `node scene/generator/generate.mjs` → `validation.passed = true`
3. `npx tsc --noEmit` → 0 错误
4. `npm run build` → 成功，dist 内无 `.map` 之外的额外文件
5. 运行时 `__WS.state().phase` 可从 `intro → fight → ko → matchEnd` 走通
