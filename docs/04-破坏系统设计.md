## 1. 三级破坏定义

| 等级 | 语义 | 本作物件 | 触发门槛 | 战斗影响 |
|---|---|---|---|---|
| **1 轻度** | 装饰碎裂 | 灯笼（7 个，程序化分布） | 任意 `destructionLevel ≥ 1` | 仅视觉 + 音效，无碰撞变化 |
| **2 中度** | 结构断裂 | 立柱 ×2、东侧墙板 ×1 | `destructionLevel ≥ 2` | 碰撞体移除；墙板破坏后**开启通道**（可绕后） |
| **3 重度** | 地面塌陷 | 中庭青石板（`floor-mid`） | `destructionLevel = 3` | 地面层高 -0.74、战斗边界被切断、坠落硬直 |

**核心决策**：只有「震地印」（李宾 2 号必杀）与「回澜棍」（筄山 1 号必杀）的第 2 段带
`destructionLevel = 3`，且冷却 60–90 帧。因此一局之内「轻度→中度→重度」是可感知但不可刷的节奏。

## 2. 可破坏物数据字段（统一标准）

```ts
interface DestroyableSpec {
  id: string;
  tier: 1 | 2 | 3;          // 破坏等级门槛
  hp: number;                // 耐久
  stages: number;            // 阶段数（1 = 一击碎，2 = 先裂后碎）
  x, y, z: number;           // 世界坐标（脚底）
  w, h, d: number;           // 包围尺寸
  preset: string;            // 碎片外观预设（对应 fragmentPalettes）
  chainRadius: number;       // 连锁半径
  opensPassage: boolean;     // 破坏后是否开通道
  collapseZone?: { id, fromX, toX, depth }; // 三级破坏专用
  sfx: string;
}
```

- 手工设计：`manual.keyDestroyables`（立柱、墙板、地面）—— 生成器**只读复制**，不生成。
- 程序化生成：灯笼的**位置/高度/摆动相位**来自 `scene/output/decor.json`，但 `tier/hp/preset` 固定为
  `1 / 20 / paper_lantern`，不参与随机。

## 3. 破坏流程与事件顺序

```
命中 → combat:hit（含 destroyLevel）
  → Match 调用 destruction.impactAt(x, y, level, source)
    → 距离筛选（dz ≤ max(1.9, d/2 + 1.4) 且 dx ≤ w/2 + 0.95 且 dy ≤ h/2 + 1.0）
      → level < tier：仅掉 6 点耐久（"擦伤"），不推进阶段
      → level ≥ tier：damage = {1:24, 2:55, 3:120}[level]
        → destroy:damage 事件
        → 阶段推进 destroy:stage
          → 中间阶段：网格缩小 6% + 倾斜 + 预喷 4 片碎片 + 震屏
          → 最终阶段：destroy:break → 隐藏网格 / 生成碎片 / 连锁 / 塌陷
```

**连锁**：破坏物 A 破碎时，半径 `chainRadius` 内、等级 ≤ A 的物件进入 8 帧延迟队列，
8 帧后各自承受 40 点伤害（可继续引发它们的破碎）。灯笼因此会成串熄灭。

**撞墙**：`Fighter.resolveHit` 判定受击方贴边且速度朝墙 → `wallSplat` →
`impactAt(墙侧 0.6, 1.4, 2)`，把立柱/墙板打碎。这是"投技撞墙"的落地方式。

## 4. 判定框与碰撞层级

| 层 | 内容 | 与角色关系 |
|---|---|---|
| L0 地面 | `floor-a/b/c`，`floor-b` 可塌陷 | 决定 `getFloorY(x)` |
| L1 边界 | `fightBounds ±5.6`（塌陷后按坑两侧收缩） | 角色 x 钳制 |
| L2 关键碰撞 | 立柱、墙板（圆/盒） | **不做角色阻挡**（只在破坏时改地形/开通道） |
| L3 判定框 | 攻击 box（相对角色） | 与角色 hurtbox 求交 |
| L4 碎片 | 纯视觉抛体 | 不与角色碰撞 |

> 取舍：立柱不做实体阻挡，避免 2.5D 平面上被卡住；其"战斗影响"通过撞墙破坏、开通道与地面塌陷体现。

## 5. 时间步与顿帧的关系

- 逻辑固定 60Hz；碎片物理也在 `DestructionSystem.update(dt)` 中按**渲染帧**推进（非固定步），
  因为碎片不参与判定，无需确定性。
- 顿帧期间逻辑冻结，但碎片继续飞 —— 视觉上"打完还在碎"，增强打击感。
- 碎片落地高度取 `arena.getFloorY(x) + 0.03`：塌陷后再碎的东西会落进坑底，不会悬在坑口。
- 坑内状态由 `Fighter.inPit` 记账，不靠 `state === 'down'` 推断：`down` 会被 Fighter 自己翻回 `idle`，
  用它记账会形成「掉进去 → 恢复 → 又判定为刚掉进去」的 42 帧死循环。
- 破坏阶段推进发生在**命中当帧**，不等待顿帧结束；`destroy:break` 事件即触发震屏与音效。

## 6. 碎片对象池

| 项 | 桌面 | 移动（中/低） |
|---|---|---|
| 池容量（预分配） | 200 | 150 / 100 |
| 单次爆发上限 | 26 片 | 26 片（写入实例矩阵，不新增 draw call） |
| 生命周期 | 3.2–5.6s | 同 |
| 物理 | 重力 0.055/帧²、地面反弹 0.32、水平摩擦 0.72 | 低档降级为只做 X 轴旋转（省 CPU） |
| 回收 | 超上限回收寿命最短者；到期缩放到 0 后回收 | 同 |

几何体只有 3 种（Box / Tetrahedron / 扁 Box），材质按预设色缓存 3–6 个，**不新建材质**。

## 7. 破坏后地形更新

1. **塌陷**：`Arena.collapse(zone)` 隐藏 `floor-b`，生成坑底 + 四壁（贯穿整个场地深度）；
   `getFloorY(x)` 返回 -0.74；`isInPit(x)` 为真。
2. **边界**：`Match.boundsFor(fighter)` 对落地角色返回坑一侧的边界，**地面无法跨越**，只能跳过。
3. **坠落**：落地且位于坑内 → `down` 状态 42 帧 → 爬出到坑边（x 吸附到 `fromX-0.5` 或 `toX+0.5`）。
4. **通道**：`Arena.openPassage(id)` 隐藏墙板网格；视觉上形成缺口（当前版本不改变可行走层）。

## 8. 存档/重置

每局开始执行两件事：

1. `DestructionSystem.reset()`：恢复 hp / stage / 网格可见性与缩放，回收所有碎片；
2. `Arena.resetTerrain()`：清空 `collapsed` 集合、恢复地面网格可见性、释放坑体网格（几何 + 材质），
   使每回合回到完好的「霜庭」。

> 早期版本漏了第 2 步，导致第二局开局就站在坑里（BUG-002，已修复，见 QA 报告第 6 节）。
> 塌陷的**战斗影响（层高/边界/坠落）只在当前回合有效**，这是设计选择：回合制格斗需要公平的初始地形。

## 9. 性能预算

| 指标 | 目标 | 实测（软件渲染环境） |
|---|---|---|
| 破坏后帧率下降 | ≤15% | 破坏前 20fps → 破坏后 18fps（SwiftShader） |
| 同屏碎片 | ≤200 / ≤100 | 峰值约 170（17 个物件全碎，v2.0.8 口径；原 13 件 / 138 片为 v2.0.7 及更早实测） |
| 碎片相关 draw call | ≤6 | **3**（三个 InstancedMesh 各 1 次，与同屏碎片数无关；实测约 170 片时总 draw call 77–82） |
| 破坏触发到首帧碎片 | ≤1 帧 | 同帧生成 |
